# Architecture

## Route groups (by role)
- `(public)` — landing/about page, no auth required.
- `(auth)` — login, forgot password, staff-invitation activation (`/activate`). Parents self-register on the mobile app, not here.
- `(manager)` — the center's **back-office**, URL `/manager/*`, shared by 4 roles: `admin` (everything), `center_manager` (staff/parent/teacher accounts, curriculum + fixed class schedule, assign teachers, business dashboard), `curriculum_designer` (curriculum only), `staff` (registration, tuition, makeup/swap/long leave/withdraw). Web only. Which role sees which screen lives in `src/constants/role-access.ts` (single source; drives sidebar, `proxy.ts` 403 and hidden cross-role buttons). The group name says "manager" for URL stability — it is NOT the `center_manager` role.
- `(teacher)` — schedule (set by the center, read-only), attendance (drives teacher work-credit), assignments, grading, reports, work-credit. Web + Mobile.
- `(parent)` — dashboard, per-child schedule/grades, child profiles, homework. Mobile only per current spec. One account can hold multiple children.

## Key folders
- `components/ui` — generated by the Shadcn CLI, don't hand-edit.
- `components/shared` — cross-role components (Header, ChildSwitcher, Sidebar). See `shared-component-architecture.md`.
- `features/<domain>` — colocate domain logic + UI instead of growing `components/` unbounded.
- `lib/validators` — Zod schemas, shared between forms and API calls.
- `hooks/` — custom hooks + TanStack Query hooks.
- `providers/` — `QueryClientProvider`, theme provider; wraps the root layout.

## Auth model
Two kinds of login account:
- **Parent** (mobile): one account = one parent, who can hold multiple child profiles (`StudentProfile`). No separate student login — a child submits homework/views grades through the parent's session. Parents self-register and create child profiles on the app.
- **Web staff** (`StaffAccount` + `Teacher`): role is one of `admin | center_manager | curriculum_designer | staff | teacher`. Role is held in the `edugrade_role` cookie (mock phase) and checked on the server by `src/proxy.ts` via `canAccessPath` in `src/constants/role-access.ts`.

## State management
- Server state: TanStack Query.
- URL state (filters, pagination, tabs): `nuqs`.
- Local UI state: React `useState`/`useReducer` — no global client store.
