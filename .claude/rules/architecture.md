# Architecture

## Route groups (by role) — 5 roles now, up from 3
- `(public)` — landing/about page, no auth required.
- `(auth)` — login, parent self-registration with email/password; parents create child profiles themselves in the app.
- `(manager)` — Quản lý trung tâm (center manager), Web: CRUD staff/teacher/parent records, dashboard (revenue, counts), create classes (subject + grade + program + room + fixed schedule), assign a teacher to an existing fixed class.
- `(curriculum)` — Thiết kế giáo trình (curriculum designer), Web, **new role**: authors per-subject curriculum content (Toán/Lý/Hóa/Sinh, based on textbooks) and lesson pacing (1 lesson/session, 1 test/month). Does not touch class scheduling or rooms — that stays in `(manager)`.
- `(staff)` — Nhân viên (admissions/operations staff), Web, **new role**: everything that used to be "manager does the day-to-day" — student registration (A1/A2/A3 enrollment flow), **payment confirmation** (moved off the manager role), schedule changes, makeup-class scheduling, permanent/long-term leave.
- `(teacher)` — Giáo viên, Web (platform note below): schedule, attendance (now also feeds teacher compensation), homework, AI-grading review/approval, reports, confirms their own fixed schedule for an assigned class.
- `(parent)` — Phụ huynh, Mobile only: create child profiles, see classes attached by staff after payment, receive/submit homework, view grades/attendance.

**Platform note — please confirm:** the role list now says "Giáo viên — Web" only, but §1.3's heading still says "(Web + Mobile)". Assumed **Web only** here since the role list is the more recently edited source; flag if teacher should keep a mobile app.

## Key folders
- `components/ui` — generated by the Shadcn CLI, don't hand-edit.
- `components/shared` — cross-role components (Header, ChildSwitcher, Sidebar). See `shared-component-architecture.md`.
- `features/<domain>` — colocate domain logic + UI instead of growing `components/` unbounded.
- `lib/validators` — Zod schemas, shared between forms and API calls.
- `hooks/` — custom hooks + TanStack Query hooks.
- `providers/` — `QueryClientProvider`, theme provider; wraps the root layout.

## Moving existing UI, not rebuilding it
Several screens simply change which route group they live under — the component code itself doesn't need a redesign:
- Student registration, payment confirmation, schedule/makeup/leave screens: `(manager)/students`, `(manager)/payments` → move to `(staff)/students`, `(staff)/payments`, etc.
- Subject/Program/Lesson/Room CRUD: `(manager)/curriculum` → move to `(curriculum)/`.
- Everything else already under `(manager)` for teacher/staff-record CRUD, dashboard, and class creation stays put.

## Auth model
One login account = one parent, who can hold multiple child profiles (`StudentProfile`). No separate student login.

## State management
- Server state: TanStack Query.
- URL state (filters, pagination, tabs): `nuqs`.
- Local UI state: React `useState`/`useReducer` — no global client store.
