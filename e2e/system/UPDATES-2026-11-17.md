## Những điểm đã sửa trong code

- API đăng ký, hóa đơn, danh sách hóa đơn và biên lai của phụ huynh chỉ lấy hoàn tiền `APPROVED`. Nhân viên vẫn đọc được đầy đủ các trạng thái để xử lý.
- Sửa điểm danh khóa dòng buổi học trước khi đọc trong transaction, dùng cùng khóa với đặt học bù. Kiểm tra giáo viên phụ trách cũng được thực hiện trong transaction. Có ca E2E chạy hai thao tác đồng thời để kiểm tra bất biến nguồn học bù phải vắng.
- Từ chối lý do chỉ có khoảng trắng khi ghi nhận hoàn tiền, gia hạn và sửa điểm danh.
- App hiển thị lỗi tra cứu đơn nghỉ và nút tải lại; chưa xác định được trạng thái thì chưa cho gửi đơn mới.
- Xác nhận thu tiền chỉ bật khi đã chọn hình thức và xác nhận nhận đủ tiền. Test ghi danh cũ đã bổ sung chọn tiền mặt.
- Khôi phục thao tác thu tiền nhận đúng trường `method` mới. Khi thử lại sau lỗi mạng, giữ nguyên hình thức, biên lai và khóa xác nhận; thao tác từ phiên bản cũ chưa có hình thức được phát lại nguyên trạng, có nhãn giải thích riêng.
- Giao diện gia hạn ghi đúng 1–90 ngày/lần; bỏ thông báo 2 lần/60 ngày không còn phù hợp với quy tắc hiện tại.
- Trang công khai chờ request để lấy dữ liệu, tránh lưu trang danh mục/liên hệ trống khi backend chưa chạy lúc build. Cache các lần lấy dữ liệu công khai thành công vẫn giữ 5 phút.

Các bản sửa trên mới được kiểm tra tĩnh; cần chạy các ca bên dưới trước khi xác nhận hành vi thực tế.

## Bạn chạy từ repo FE

Yêu cầu: Node 22+, Docker Desktop đang chạy, Microsoft Edge, dependency theo lockfile của bốn repo đã cài. Giữ cả bốn thư mục cạnh nhau. Chạy mới lần đầu để runner build đúng code hiện tại và áp dụng migration `20261115100000_tet_refund_extension_method` vào DB test riêng. Không dùng `--reuse` với server từ phiên bản cũ.

```powershell
Set-Location 'D:\kỳ 8\WDP301-FE-System'

# Phần mới: mở trình duyệt và chạy 16 kịch bản gắn @updates.
npm run test:e2e:updates -- --headed

# Toàn hệ thống: demo, nghiệp vụ mới, route, UI, Admin và app phụ huynh.
npm run test:e2e:all -- --headed

# Xem kết quả sau lần chạy (mỗi lần ghi lại báo cáo system).
npm run test:e2e:system:report
```

Runner tự dựng API/web/Admin/Expo Web, MySQL/MinIO riêng, quay video/chụp ảnh/trace. Dịch vụ tự dừng khi chạy xong; dữ liệu test được giữ cho lần sau. Nếu cổng báo đang bị chiếm, dừng phiên test cũ hoặc dịch vụ đang dùng cổng đó trước khi chạy lại; không tắt tùy tiện mọi tiến trình Node.

Muốn tự thao tác trên UI hoặc dùng giao diện chọn test:

```powershell
# Terminal 1: dựng code hiện tại và giữ các dịch vụ.
node e2e/demo/run.mjs --system --serve

# Terminal 2: chọn test và xem từng bước.
npm run test:e2e:ui
# Hoặc chạy riêng phần mới trên đúng môi trường đó.
npm run test:e2e:updates -- --reuse --headed
```

Kết quả nằm ở `e2e/.system-report`, `e2e/.system-results`. Dữ liệu đăng nhập/runtime bị Git bỏ qua.

## Kiểm tra tĩnh của lượt chuẩn bị

Prisma client đã được sinh theo schema mới, không áp dụng migration hay kết nối DB. Các kiểm tra sau đã hoàn tất:

- TypeScript `--noEmit --incremental false`: toàn bộ source web, backend và mobile; riêng bộ Playwright dùng `tsconfig.e2e.json`.
- ESLint: các file source/test được sửa ở web và backend, với `--max-warnings=0`; component mobile được sửa cũng không có lỗi/cảnh báo.
- Prettier: các spec mới/mở rộng, helper, bộ đọc thao tác thu tiền, hộp xác nhận và component mobile đạt định dạng.
- `git diff --check`: không có lỗi khoảng trắng ở ba repo có sửa. Admin vẫn sạch, đúng mốc nguồn.
- Rà soát source độc lập: đã xử lý các điểm về tra cứu đăng ký chưa thu tiền, kiểm tra tệp bị lặp, chờ khóa đồng thời và tương thích thao tác thu tiền cũ. Không còn phát hiện quan trọng trong phạm vi đã đọc.

Đếm source có 14 test mới và 76 `page.tsx` web, gồm `/manager/payments`; đây là kiểm tra source, **không phải kết quả chạy route/test**. Chưa có build hoặc kết quả test mới để khẳng định toàn hệ thống đã hết lỗi. Lần chạy của bạn sẽ kiểm chứng selector, transaction, UI thực tế và xuất báo cáo hiện tại.
